+
What retrieval adds nowRelevant passages selected for this question.

RAG = retrieval-augmented generation. It changes the context—not the model’s weights.

By the end: explain each stage · inspect one retrieval trace · diagnose one failure.

Retrieval design · four common patterns

RAG is not one fixed recipe.

Same goalAssemble the best evidence packet for the question—then generate from that packet.

  1. 01exact
    Lexical RAGBM25 · keywords
    Best for: names, product codes, quotations, document IDs. Example: “EXALGO 12 mg” or “ffgf0232.”
  2. 02meaning
    Vector RAGembeddings · semantic similarity
    Best for: paraphrases and related concepts. Example: “How was dependence risk framed?”
  3. 03both
    Hybrid RAGlexical + vector + filters
    Best for: mixed research archives. Example: semantic topic + exact drug name + date/genre filter.
  4. 04iterate
    Multi-step / agentic RAGplan · search · repeat
    Best for: questions requiring several evidence roles. Example: retrieve public claims and internal messaging separately, then compare.
Practical defaultStart hybrid.

Use exact matching for identifiers, semantic search for meaning, metadata for scope, and reranking when the corpus grows.

Presenter notes

Purpose
Show that RAG describes a family of architectures. The generator can be similar while the retrieval strategy changes substantially.
Lexical
Keyword-oriented methods such as BM25 are strong when exact terms matter: names, codes, quotations, and record identifiers.
Vector
Dense embeddings help when the question and the source express the same idea with different words.
Hybrid
Combine lexical and vector scores, then apply metadata filters or a reranker. For a heterogeneous archive, this is usually the most sensible starting architecture.
Agentic
A model may decompose a complex question, generate several searches, inspect results, and retrieve again. This can improve coverage but adds cost, latency, and new failure surfaces.

Transition
